# 要件定義書：読書記録アプリ（本棚アプリ）

## 1. 概要

個人の読書記録を管理する、シンプルな本棚Webアプリケーション。
スクール課題（初級編最終課題）として開発する。

## 2. 背景・目的

- スクールの初級編最終課題として取り組むものであり、特定の業務課題やビジネス上の目的があるわけではない
- 主目的は学習：指定技術スタック（Next.js / Ruby on Rails / MySQL）での要件定義〜設計〜実装という開発の一連の流れを一人で経験し、身につけること
- 副次的な狙いとして、実際に自分の読書記録に使えるものを作ることで、成果物としての実用性・学習の定着度を高める

## 3. 想定利用者

- 開発者本人のみ（1ユーザー）
- ログイン・認証機能は不要（前回のTrello風アプリと同様の方針を踏襲）

## 4. スコープ

### 4.1 今回実装する範囲（MVP）

- 書籍の登録・編集・削除
- ステータス管理（未読／読書中／読了）と、カンバンのカラム移動と同様のドラッグ&ドロップによるステータス変更
- 読了時の完了日入力
- 1ヶ月単位の読書量集計（指定月の読了冊数＋直近12ヶ月の月別読了冊数グラフ）
- 評価（星1〜5）・感想メモの記録（書籍1件につき1件のシンプルな形）

### 4.2 将来的に追加したい範囲（今回は対象外）

- 感想メモを複数回に分けて記録できる「フィード」形式への拡張（読書中の途中経過メモを都度追加できる等）
- 書籍の検索・タグ・ジャンル分類
- 複数の本棚（カテゴリ別の本棚切り替え）
- ログイン・複数ユーザー対応

### 4.3 明確に対象外とするもの

- 他ユーザーとの読書記録の共有・SNS的機能
- 書影・書誌情報の外部API（Google Books等）からの自動取得

## 5. 機能要件

書籍を1件のリソースとして登録し、ステータス（未読／読書中／読了）で管理する。ステータス変更はカンバン風のドラッグ&ドロップUIで行う。読了時には完了日を入力できる。月ごとの読了冊数を集計して表示する。評価・感想メモは書籍ごとに1件記録できる。

### 5.1 書籍の登録項目

| 項目 | 必須 | 内容 |
|---|---|---|
| タイトル | ○ | テキスト |
| 著者名 | － | テキスト |
| 書影画像URL | － | 手入力したURLの画像をカードに表示する（外部APIからの自動取得はしない）。未入力時はプレースホルダ表示 |
| ステータス | ○ | 未読／読書中／読了。新規登録時の初期値は「未読」 |
| 読書開始日 | － | 日付。「読書中」への移動時に自動セット（後述） |
| 完了日 | － | 日付。「読了」への移動時に自動セット（後述） |
| 評価 | － | 1〜5の整数（星5段階）。ステータスが「読了」の書籍のみ入力可。未評価も可 |
| 感想メモ | － | 自由記述テキスト。ステータスに関係なく入力可 |

### 5.2 書籍の登録・編集・削除

- 本棚ボード画面から新規登録できる。登録した書籍は「未読」列の末尾に追加する
- カードを選択すると編集モーダルが開き、上記すべての項目を編集できる
- 編集モーダルから削除できる。削除前に確認ダイアログを表示する

### 5.3 ステータス管理（ドラッグ&ドロップ）

- ボードは「未読」「読書中」「読了」の3列で構成する
- カードを列間でドラッグ&ドロップするとステータスが変わる
- 同じ列の中でもドラッグ&ドロップで自由に並べ替えでき、並び順は保存される（再読み込み後も維持）
- ステータス変更時の日付・評価の扱いは以下のとおり

| 移動 | 読書開始日 | 完了日 | 評価 |
|---|---|---|---|
| → 読書中 | 未入力なら今日の日付を自動セット | クリア | クリア |
| → 読了 | 変更しない | 今日の日付を自動セット | 変更しない（読了後に入力） |
| → 未読 | クリア | クリア | クリア |

- 自動セットされた日付は、編集モーダルで後から任意の日付に修正できる
- 感想メモはステータスが変わってもクリアしない
- 「未読」から「読了」へ直接移動した場合、読書開始日は未入力のままとする

### 5.4 月間読書量集計

- 集計対象は、ステータスが「読了」で完了日が入力されている書籍とする。完了日の年月で集計する
- 指定月の読了冊数を表示する。初期表示は今月とし、前月／翌月に切り替えられる
- 直近12ヶ月（今月を含む）の月別読了冊数を棒グラフで表示する。読了0冊の月も0として表示する

### 5.5 評価・感想メモ

- 評価・感想メモは書籍1件につき1件とし、編集モーダルから入力・更新する
- 評価は「読了」の書籍のみ入力でき、読了以外へ戻すとクリアされる（5.3参照）

## 7. 非機能要件

- 対応端末：PCのみ（デスクトップブラウザ。最新版のChromeで動作確認する）。スマートフォン・タッチ操作には対応しない

- 利用者：1ユーザー（開発者本人）。認証なしのため、外部公開はしない前提とする
- 性能：個人利用の規模（書籍数百件程度）で操作が快適に行えること
- データ保全：データはMySQLに永続化し、コンテナを再起動しても消えないこと

## 10. 主な仕様判断とその理由

要件を決める際に検討した選択肢と、採用した理由を記録する。

| 論点 | 採用した仕様 | 検討した他の案 | 採用理由 |
|---|---|---|---|
| 登録項目 | タイトル・著者名・書影画像URL・読書開始日（＋完了日・評価・感想メモ） | 総ページ数 | 読書記録として最低限必要な情報に絞った。読書開始日と完了日があれば読了までの期間がわかる。総ページ数は集計を冊数ベースとしたため今回は不要と判断 |
| 書影画像 | URLを手入力して表示 | 外部API（Google Books等）で自動取得／画像アップロード | 外部APIは対象外（4.3）。アップロードはファイル保存の仕組みが必要になり、MVPとしては複雑さが見合わないため、URL指定のみとした |
| 評価の形式 | 1〜5の整数、読了時のみ入力可 | 読了以外でも入力可／0.5刻み | 評価は読み終えてから行うものなので、読了時のみとした。半星はUIが複雑になるわりに効果が小さいため整数にした |
| 完了日の入力方法 | 読了列へのドロップ時に今日の日付を自動セットし、後から編集可 | ドロップ時に日付入力ダイアログを表示 | 読み終えた当日に記録するケースが多く、毎回ダイアログが出ると操作が止まってしまう。違う日付のときだけ修正すればよい |
| 読書開始日の入力方法 | 読書中列への移動時に今日の日付を自動セット（既に入力済みなら変更しない） | 手入力のみ | 完了日と同じ考え方で入力の手間を減らすため。入力済みの日付を上書きしないのは、読書中と読了を行き来しても最初の開始日が残るようにするため |
| 読了から戻したときの扱い | 完了日・評価をクリア（未読まで戻すと開始日もクリア）。感想メモは保持 | すべて保持 | 評価は「読了時のみ」としたため、読了でない本に評価や完了日が残ると矛盾する。また、完了日が残ると月間集計の冊数とも食い違う。感想メモは読書途中でも書く内容なので残す |
| 未読→読了へ直接移動したときの開始日 | 未入力のまま | 完了日と同じ日を自動セット | 実際の開始日はわからないため、推測で値を入れず空欄にした。必要なら手入力できる |
| 列内の並び順 | ドラッグ&ドロップで自由に並べ替え、順序を保存 | 日付順で自動整列 | カンバンらしい操作感にするため（前回のTrello風アプリと同様）。「次に読みたい本を上に置く」といった使い方ができる |
| 新規登録した本の位置 | 未読列の末尾 | 未読列の先頭 | 登録した順に並ぶほうが自然なため。優先したい本はドラッグで上に移動できる |
| 月間集計の表示 | 指定月の冊数（前月／翌月に切り替え可）＋直近12ヶ月の棒グラフ | 冊数のみ／グラフのみ | 「今月何冊読んだか」はひと目でわかる数値で、推移はグラフで見られるようにするため |
| 集計の基準 | 完了日の年月 | ステータスを読了に変えた日 | 完了日は後から修正できるため、実際に読み終えた日で集計するほうが正確になる |
| 削除時の確認 | 確認ダイアログを表示 | 確認なしで即削除 | 削除すると元に戻せないため、誤操作を防ぐ |
| 対応端末 | PCのみ | PC＋スマートフォン | スマートフォンに対応するにはレスポンシブ対応とタッチ操作でのドラッグ&ドロップが必要になり、工数が増える。主目的は開発工程の学習なので、範囲を絞った |
| 動作環境 | ローカル（Docker）のみ | 本番環境にデプロイ | 認証機能がないため、外部に公開すると誰でもデータを操作できてしまう。Dockerを使えば、フロントエンド・バックエンド・MySQLを1コマンドで同じ構成のまま起動できる |
